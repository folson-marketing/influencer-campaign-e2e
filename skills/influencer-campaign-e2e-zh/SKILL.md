# 红人营销 Campaign 全流程（中文版）

把一次红人营销从头跑到尾，并把所有红人沉淀进可复用的**红人资源库**。流程共 9 个阶段，每个阶段都读写同一个数据库，所以可以随时中断、下次接着跑。

本 Skill 是面向中文用户的版本：说明、对话和数据库字段以中文为主（字段附英文，方便跨团队协作），外联文案默认中文。给英文或其他语言的红人写邮件时，用对方的语言改写模板。英文团队请使用英文版 `influencer-campaign-e2e`。

## 工具：按能力找工具，不写死工具名

本 Skill 可以在不同的 Agent 里运行（Claude.ai、Claude Code、Codex 等），每个 Agent 的工具名不一样。下面写的都是**能力**，用当前环境里能提供这个能力的工具；都没有就走兜底方案。

| 能力 | 用什么 | 没有时的兜底 |
|---|---|---|
| 向用户提问 | 结构化选择题工具 | 在对话里列出编号选项让用户回复 |
| 表格 / 数据库 | 飞书多维表格、Google Sheets / Drive、本地 Excel 相关工具 | 生成 `.xlsx` / `.csv` 让用户导入 |
| 红人数据 | Apify，或其他红人数据工具（Bizkol、Modash、HypeAuditor 等） | 用浏览器在平台搜索页读取；再不行让用户粘贴主页数据 |
| 邮件 | Gmail、Outlook / Microsoft 365 相关工具 | 输出邮件文案，让用户自己发（企业邮箱、QQ 邮箱等同理） |
| 网页浏览 | 任何浏览器自动化或网页抓取工具 | 让用户打开页面并粘贴需要的内容 |
| 店铺 / 折扣码 | Shopify 相关工具 | 让用户自己建折扣码后发回来 |

缺某个能力时：
1. 如果 Agent 能搜索或推荐连接器 / MCP，就用它推荐安装。
2. 否则明确告诉用户要装什么、怎么装（见 `references/setup.md`）。
3. 让用户选：**安装** / **用兜底方案** / **换一个方案**。不要卡住不说话。

## 数据完整性（每个阶段都适用，不可省略）

完整清单见 `references/data-integrity.md`。要点：

1. **写入前先校验**：必填字段齐全、数字是数字、没有重复红人（同平台 + 同账号，或同一邮箱对应多个账号）。
2. **写入后回读核对**：每次写入在线表格（飞书、Google Sheets、共享文件）后，把刚写的行读回来，和预期逐项对比。发现错位、截断、乱码，先修好再继续，并告诉用户。
3. **估算值当场标注**：所有估算或替代指标在出现的地方直接标注，如 `约 12,000（估算）`，并在该行的 `数据可信度 Data Confidence` 字段填「已核实 / 估算 / 替代指标」。只写在隐藏备注里不算。
4. **数字合理性检查**：看起来不合理的数值要标出来给用户看，不要悄悄保留或删除（阈值见参考文件）。
5. **不悄悄丢数据**：某行或某字段写不进去，说清楚是哪条、为什么。
6. **说明数据来源**：每次采集新数据，都说出用的工具 / actor 和具体搜索词，并记录在 `数据来源 Source` 和 `搜索词 Search Query` 字段。

## 给用户展示红人

- **入选名单和头部候选（最多约 10 个）：每人一张资料卡。** 平台；账号及主页链接；粉丝数；垂类；互动指标**及计算方式**（如「互动率 3.4% = 近 12 条内容的平均（点赞 + 评论 + 收藏）÷ 粉丝数」）；联系方式情况（有邮箱 / 只能私信 / 暂无）；总分及各维度得分；数据可信度和风险提示。
- **其余候选：一张紧凑的排序表**（账号、平台、粉丝、互动率、分数、分级），候选多时也清晰易读。

## 每个阶段结束时

每个阶段收尾都要给出：
- **数据库链接**（本地 Excel 则给文件名），
- **本次新建或修改的内容汇总**：哪些表、新增 / 更新 / 标记了多少行，
- **下一步**，一句话说明。

## 阶段 0：初始化

每个新 Campaign 必做；老 Campaign 先读配置。

1. **有现成配置吗？** 用户给了已有的表格链接或文件，先读 `_Config / 配置` 表，拿到数据库类型、链接、发件邮箱、品牌信息，直接跳到用户要做的阶段。
2. **收集 Campaign Brief**（一次问完）：品牌 / 产品、落地页或店铺链接；目标（曝光 / 转化 / 内容素材 UGC / 下载注册）；目标市场与语言（如中国大陆、北美华人、北美英文）；平台（小红书 / 抖音 / B站 / 微博 / 视频号 / TikTok / Instagram / YouTube / 其他）；红人量级（素人 Nano 1k–10k / 腰部 Micro 10k–100k / 中部 Mid 100k–500k / 头部 Macro 500k+）；合作方式（寄样置换 / 固定费用 / 佣金 / 混合）；预算、单个红人费用上限、目标红人数量、上线时间窗口；内容要求（必须出现的卖点、禁用词、是否审稿、是否要授权二次投放）。
3. **选择数据库**：飞书多维表格 / Google Sheets / 本地 Excel。检查对应能力，缺了按上面的方式处理。详见 `references/setup.md`。
4. **选择红人数据源**：默认 Apify。详见 `references/setup.md`。
5. **建库**：按 `references/schema.md` 建表。已有表就只补缺失字段，不要覆盖。

## 阶段 1：找红人

1. **先查资源库**：在红人资源库里筛选垂类、平台、A/B 级、非黑名单、近 60 天没被联系过的人，优先复用。
2. **再补新人（Apify 或其他红人数据工具）**：
   - 按平台搜索评分高、维护中的 actor（主页、话题、搜索类爬虫），先看输入参数再运行，不要写死 actor 名。找不到对应平台的 actor（部分国内平台较少），就改用浏览器。
   - 搜索策略：品类关键词 + 话题标签 + 竞品品牌名（找给竞品做过内容的红人）+ 目标地区。
   - **每次运行前，告诉用户用哪个 actor、搜哪些词。**
   - 先跑小批量（每个关键词 20–50 条）确认数据质量和成本，再告诉用户预估消耗后扩量。
   - 提取：账号、粉丝、近 10–20 条内容的播放 / 点赞 / 评论 / 收藏、简介里的邮箱、微信或其他联系方式。
3. **浏览器方式**：在平台搜索页、话题页逐个打开主页，读取同样字段。告诉用户这种方式更慢，每次建议 20–30 个候选。
4. 做完数据完整性检查后写入红人资源库（按平台 + 账号去重，已存在则更新）和合作进度表（阶段 = `待评估 Sourced`），写完回读核对。
5. 展示结果：头部候选用资料卡，其余用紧凑排序表。

## 阶段 2：评估打分

按 `references/scoring.md` 的规则给每个候选打 0–100 分，把总分、各维度得分和打分理由写进数据库。分级：**A** ≥ 75，**B** 60–74，**C** < 60（C 默认不联系）。用资料卡展示入选名单，用户确认后阶段 → `已入选 Shortlisted`。

## 阶段 3：生成外联文案

按 `references/outreach.md` 的规则和模板，给每个入选红人写个性化的首封邮件；只能私信的红人写私信版本。以列表形式给用户过目（红人、分数、标题、正文），用户可逐条修改。

## 阶段 4：发送

1. 先问用户用哪个邮箱（Gmail 或 Outlook / Microsoft 365），记进 `_Config`。其他邮箱没有对应工具时，输出文案让用户自己发。
2. **默认先建草稿**，告诉用户去邮箱检查。只有用户明确说「发送」才发送，发送前列出收件人清单再确认一次。
3. 分批发：每批 ≤ 20 封，避免被判为垃圾邮件。
4. 没有邮箱的红人：给出私信版文案（≤ 300 字），让用户在小红书、抖音等平台手动私信，或通过微信 / MCN 联系。
5. 发送后：阶段 → `已联系 Contacted`，记录首封邮件时间和线程链接，下一步日期 = 今天 + 4 天。

## 阶段 5：跟进

每次运行时先扫描合作进度表里 `下一步日期 ≤ 今天` 的行，并搜索邮箱看有没有新回复。
- **节奏**：首封后 +4 天第 1 次跟进，再 +5 天第 2 次（最后一次，语气轻松，「不合适也没关系」）。2 次后仍无回复 → 阶段 = `无回复 No Response`，90 天内不再联系。
- 跟进要**在原线程回复**，同样默认草稿。
- **有回复时**：总结对方意图（接受 / 报价 / 提问 / 拒绝），给出建议回复草稿，更新阶段。

## 阶段 6：合作管理

- **谈判**：把对方报价与预算、同量级市场价、红人分数对比，给用户谈判建议（如打包多条内容、加佣金降固定费）。记录成交价和合作方式。
- **确认后发 Brief**：一页纸，包含产品卖点、必须包含 / 禁止内容、话术示例、CTA、专属链接和折扣码、交付物与截止日期、审稿流程、授权范围，以及广告标注要求（如「广告」/ 合作标识 / #ad，按平台规则和当地法规）。
- **专属追踪**：为每个红人生成 UTM 链接（`utm_source={platform}&utm_medium=influencer&utm_campaign={campaign_id}&utm_content={handle}`）；用户用 Shopify 且已连接时，可以为每个红人建专属折扣码。
- **寄样**：收集收货地址（只存在合作进度表里，不写入资源库），记录单号，阶段 → `已寄样 Shipped`。
- **提醒**：截止日前 3 天生成友好提醒草稿。
- **审稿**：对照 Brief 检查初稿，列出需要修改的点。
- **付款**：内容发布并核对后，阶段 → `已结算 Paid`。

## 阶段 7：效果追踪

- 在发布后第 **3 / 7 / 30** 天采集数据：用 Apify 或浏览器抓帖子的播放、点赞、评论、收藏、分享，或让用户上传红人给的后台截图。每次都注明数据来源。
- 转化数据：UTM 点击和转化从 GA4 或用户的分析工具取；折扣码订单从 Shopify 取（若已连接）。
- 计算：**CPM** = 费用 ÷ 播放 × 1000；**CPE** = 费用 ÷ 互动；**CPA** = 费用 ÷ 转化；**ROAS** = 销售额 ÷ 费用（寄样把产品成本 + 运费算进费用）。任何输入是估算值时，结果也要标为估算。
- 输出 Campaign 汇总：总花费、总曝光、总互动、转化、ROAS、Top 5 / Bottom 5 红人、效果最好的内容角度和钩子。用户要图表时，如果 Agent 有数据可视化相关指引就按指引做。

## 阶段 8：复盘与再次合作

- 按效果更新红人资源库：历史 ROI、合作次数、分级（效果好升 A，差降 C），写合作体验备注（响应速度、配合度、是否准时）。违约或内容违规 → 拉黑并写原因。
- A 级红人：生成复投邀请草稿（提到上次的好数据，提出长期合作 / 年框 / 佣金升级）。
- 效果好的内容：建议用户申请授权做付费投放（如小红书聚光、抖音 DOU+ / 千川、Spark Ads、Partnership Ads）。
- Campaign 阶段 → `已复盘 Closed`，关闭所有相关的合作进度行。

## 阶段 9：资源库维护（每次运行顺手做）

- 合并重复红人。
- 数据超过 90 天的，下次用前先刷新粉丝和播放。
- 一句话报告：库里总人数、各分级人数、本次新增人数。

## 每次运行的默认动作

用户只说「跑一下红人 Campaign」或类似时：
1. 读 `_Config` 和合作进度表。
2. 列出今天要做的事：待跟进、有新回复、快到截止、待采集数据。
3. 问用户要推进哪些（多选），然后逐个执行。

## 规则

- **不经用户确认，绝不发送邮件、不下单、不付款。**默认只建草稿。
- 只采集公开数据；遵守平台规则；不抓私密账号。个人住址和电话只存在合作进度表，不外发。
- Apify 每次扩量前说明预计结果数和大致成本。
- 所有邮件包含「不再打扰」说明，尊重「不需要」的回复并立即标记。
- 不编造红人数据、效果数据或报价；拿不到的字段留空并注明原因。
- 写数据库前先读最新版本，只追加或更新对应行，不整表覆盖。
