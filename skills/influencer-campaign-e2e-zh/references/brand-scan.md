# 品牌扫描

只要用户提供了品牌名（自己的品牌或竞品），就执行品牌扫描。目标是通过公开数据，找出**与该品牌相关的所有红人和内容**，并全部存进数据库。

## 1. 列出搜索词

搜索前先列出以下搜索词，给用户看：
- 品牌名，包括常见写法和空格变体（如「Glow Lab」「GlowLab」「glowlab」）
- 品牌在各平台的官方账号（`@glowlab`），用户没给就先找出来
- 品牌话题标签（`#glowlab`、`#glowlabpartner`、活动话题）
- 主打产品名
- 折扣码和联盟链接特征（如「code GLOW」、品牌的联盟 / 店铺域名）

请用户补充遗漏的内容（旧品牌名、活动话题、产品名等）。

## 2. 去哪里找

覆盖 Brief 里的每个平台（默认 TikTok、Instagram、YouTube）：

| 信号 | 在哪里找 |
|---|---|
| 付费合作标签 | 标有「Paid partnership with {品牌}」/ 品牌合作内容的帖子 |
| 被标记的帖子 | 品牌账号的「被标记 / 提及」页 |
| @提及 | 文案或视频描述里提到品牌账号 |
| 品牌话题 | 话题页、话题类爬虫 |
| 关键词提及 | 平台搜索，文案 / 标题 / 描述搜索，能拿到时也搜视频字幕 |
| 折扣码 / 联盟链接 | 文案、视频描述、主页外链页面 |
| 品牌转发 | 品牌自己账号转发或展示过的红人 |

用 Apify actor（主页、话题、搜索、帖子类爬虫）或浏览器，并遵守 `SKILL.md` 里的采集规则：每次运行前说明 actor 和搜索词，先跑小批量，全量扫描前给出成本预估。

## 3. 一直搜到没有新结果

- 每个搜索都要翻页，直到不再出现新内容，不要只看第一页。
- 默认时间范围：近 12 个月。问用户是否需要更长。
- 帖子按链接去重，红人按平台 + 账号去重。
- **如实说明覆盖范围。** 平台搜索不可能真正返回全部内容，所以「全部」指的是这些数据源能搜到的全部。报告搜了什么、每个搜索返回多少条，以及遇到的限制（私密账号、已删除内容、频率限制、没有可用 actor 的平台）。

## 4. 给每条内容分类

为每条内容填写 `提及类型 Mention Type`：
- **付费合作**：有平台付费合作标签、#ad / #sponsored，或明确披露了赞助
- **联盟 / 佣金**：有折扣码或联盟链接，但没有付费标签
- **寄样**：披露了「gifted」/「PR package」
- **自然提及**：提到或标记了品牌，但看不出有合作
- **品牌转发**：出现在品牌自己的账号上

证据不明确时，选最接近的类型，并把 `数据可信度 Data Confidence` 标为「估算」。

## 5. 存进数据库

- **品牌相关内容表**：一条内容一行（字段见 `references/schema.md`）。
- **红人资源库**：新增或更新找到的每个红人（按平台 + 账号去重）。加上标签 `brand:{品牌}` 和 `{提及类型}:{品牌}`（如 `paid:glowlab`），并填写 `数据来源 Source` 和 `搜索词 Search Query`。
- **合作进度表**：如果有进行中的 Campaign，先问用户是否把这些红人加进去（阶段 = `待评估 Sourced`），不要自动添加。
- 遵守数据完整性规则：写入前校验，写入后回读核对。

## 6. 向用户汇报

- 总数：找到的内容数、去重后的红人数，以及按平台、按提及类型的分布。
- 按影响力排名的头部红人用资料卡展示，其余用紧凑表格。
- 这些结果意味着什么：
  - **自己的品牌**：自然提及的红人是「暖线索」；过去的付费合作红人可以考虑复投（先看历史效果）。
  - **竞品**：这些红人已经在这个品类里做内容；标出正在和竞品付费合作的人（可能有排他条款）。
- 数据库链接，以及本次新增或更新内容的汇总。
